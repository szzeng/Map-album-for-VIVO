## 3. 实施阶段

### 阶段 A：UI 基础组件与主页

1. 建立统一颜色、字号、圆角、间距和图标资源。
2. 地图继续全屏显示。
3. 实现顶部品牌卡、真实数据状态和更多菜单。
4. 移除正式界面的纵向开发按钮。
5. 实现右下角「定位当前位置」按钮，不能再作为适配全部照片按钮。
6. 适配状态栏、导航栏和手势安全区域。
7. 不使用写死的广州默认地图视野。
8. 右下角定位按钮在面板收起/展开时始终位于面板上方，不被遮挡。

### 阶段 B：统一底部照片面板

1. 实现收起和展开两种状态。
2. 收起状态约 112dp，显示当前范围标题、数量和最多 4 张缩略图。
3. 展开状态约可用高度 68%，最多不超过 75%。
4. 展开后显示三列惰性照片网格。
5. 点击多照片聚合标记时，切换为「此处照片」模式。
6. 提供「返回当前区域」入口。
7. 不再使用独立 AlertDialog 展示聚合照片。
8. 处理面板拖动与网格滚动手势冲突。
9. 地图视野变化时更新当前区域照片，但不打断聚合组浏览。

优先使用现有 Android Views。若项目已有合适的 BottomSheet 依赖可复用；否则实现轻量自定义面板，不为一个面板引入大型依赖。

### 阶段 C：地图标记与聚合视觉

1. 统一单张照片标记的尺寸、描边和圆角。
2. 统一聚合数量角标，超过 999 显示 999+。
3. 聚合封面优先选择最新且缩略图可用的照片。
4. 封面失败时回退下一张，全部失败时显示占位。
5. 聚合代表点使用成员屏幕坐标中心，再通过地图投影得到显示位置；不得修改照片 GPS。
6. 单张照片标记点击后直接打开原生查看器。
7. 多张聚合标记点击后打开统一底部面板。
8. 尽量复用成员不变的 Marker 和 BitmapDescriptor。
9. 地图移动期间取消过期缩略图请求，停止后约 200ms 更新。

### 阶段 D：补回图迹内部照片预览页与原生相册

本阶段是必做功能。不能因优先复用 vivo 原生相册而删除图迹内部预览页。

1. 新增全屏 PhotoPreviewActivity（或与现有架构等效的独立全屏页面），不得使用 AlertDialog 代替。
2. 页面顶部 56dp 工具栏：返回、标题「照片预览」、当前序号「3 / 28」。
3. 中间照片区域约占可用高度 55%～60%，深色背景 #171B20，图片 fitCenter，不裁切。
4. 使用系统缩略图接口按需加载当前照片，初始请求最大约 1080px，不直接解码完整原图。
5. 支持双指缩放和拖动查看预览细节，最大缩放参考 4 倍；清楚标识预览分辨率有限。
6. 底部显示拍摄时间；缺失时明确显示未知或系统时间回退。
7. MediaStore 有相对路径时可显示简短路径，没有则隐藏，不显示 URI、媒体 ID 或精确 GPS。
8. 提供上一张/下一张按钮和左右滑动；显示当前序号。
9. 从当前区域网格进入，只能在进入时的当前区域集合中切换。
10. 从聚合组进入，只能在该聚合组集合中切换。
11. 从单张地图标记进入，照片集合只有该照片，切换按钮禁用。
12. 进入预览页时固定照片集合快照和排序，地图视野刷新不得改变切换顺序。
13. 提供主按钮「在原生相册中查看原图」，使用标准 ACTION_VIEW、document URI、image/* MIME 类型和读取授权。
14. 优先由 vivo 原生相册显示高清原图；不依赖未公开私有 Intent。
15. 原生相册无法打开时留在预览页并提示。
16. 从原生相册返回先回到图迹预览页；从预览页返回地图后恢复地图、面板模式及滚动位置。
17. 移除旧的 AlertDialog 预览方式，但保留/迁移 ZoomablePreview 的缩略图缩放能力到全屏预览页。
18. 正常打开和返回照片时不得重新全量查询 Provider 或重建全部标记。

### 阶段 E：当前位置按钮与单次定位

右下角按钮必须表示并执行「定位当前位置」，不是「适配全部照片」。

1. 将现有 fit/maximize 图标替换为定位/准星图标，按钮 48dp。
2. 按钮锚定地图右下角，距右侧 16dp、距底部照片面板顶部 16dp；面板展开后同步上移。
3. 删除按钮点击时调用 fitSamples() 的行为；不再把「适配全部照片」放在右下角。
4. Manifest 移除 ACCESS_COARSE_LOCATION 和 ACCESS_FINE_LOCATION 的 tools:node="remove"，改为正常声明前台权限。
5. 增加 implementation 'com.baidu.lbsyun:BaiduMapSDK_Location:9.7.0'，保留现有 Map 9.0.0 和 Util 9.0.0；不要同时添加互斥的 Location_All。构建前检查官方兼容说明。
6. 按百度官方文档添加 com.baidu.location.f 服务。
7. 定位 SDK 隐私同意必须在实例化 LocationClient 之前完成；将定位功能纳入隐私说明，明确只在用户点击时请求。
8. 用户首次点击按钮时才申请 ACCESS_COARSE_LOCATION 和 ACCESS_FINE_LOCATION 运行时权限；兼容 Android 12+ 仅授予大致位置。
9. 不申请 ACCESS_BACKGROUND_LOCATION，不在启动时自动定位，不做持续跟踪。
10. 仅发起单次定位；成功、失败或超时后停止定位并释放监听/客户端。
11. 成功后在百度地图显示当前位置蓝点及精度圈，将地图中心移动到当前位置；不修改照片 GPS。
12. 坐标必须根据定位回调返回的实际坐标类型处理。国内地图与 BD09LL 对齐；海外 WGS84 不能直接当成 BD09LL，也不能重复转换。
13. 权限拒绝、系统定位关闭、定位超时和定位失败均显示简短提示；不影响照片地图的其他功能。
14. 不记录定位历史，不将当前位置持久化，不上传到图迹自有服务。
15. 核实定位 SDK 的 AK、包名和签名限制。复用本地 AK 配置仅限确认官方要求允许；任何新增 AK 只能放入被 Git 忽略的本地配置，不得提交。

官方参考：
- https://lbsyun.baidu.com/docs/android?title=android-locsdk%2Fguide%2Fcreate-project%2Fandroid-studio
- https://lbs.baidu.com/docs/android?title=android-locsdk%2Fandroid-privacy
- https://lbs.baidu.com/docs/android?title=androidsdk%2Fguide%2Fcreate-map%2Flocation

### 阶段 F：缩略图与列表性能

1. 继续使用 ThumbnailLoader。
2. 地图缩略图请求约 144～160px。
3. 网格缩略图约 300～360px，按屏幕密度调整。
4. 继续使用 32MiB LRU、两个后台线程和有界队列作为初始策略。
5. 只加载可见项及少量预取项。
6. 避免视图复用导致旧图片闪现到新位置。
7. 缓存 Bitmap 不得被 View 任意 recycle。
8. 不保存磁盘缩略图。
9. 不因为 UI 更新重复读取 Provider。

### 阶段 G：Debug 与正式入口区分

1. 身份核验入口继续保留。
2. 选择测试照片、清空样本、诊断入口放入 Debug 菜单。
3. 正常界面不出现开发按钮。
4. 受限样本模式必须明确显示「样本模式」和真实样本数量。
5. 不显示虚构的全图库总数或加载进度。
6. 不因 UI 改造开放全图库读取。

## 4. 必须保留的安全边界

- MapDataRepository 的 IDENTITY_UNVERIFIED 状态不得删除或绕过。
- 不修改 vivo Provider 数据。
- 不扫描全部照片 EXIF。
- 不建立照片/GPS 持久化数据库。
- 不建立磁盘缩略图库。
- 只增加用户主动点击时所需的前台粗略/精确定位权限；不增加后台定位权限。
- 不记录当前位置历史，不将当前位置写入照片数据或上传到图迹自有服务。
- 不将真实照片、精确 GPS、媒体 ID 或私人路径写入日志和测试报告。
- 广州范围过滤只有在独立完成多城市坐标验证及正式地域策略后才能移除；不得为了 UI 看起来完整而直接删除安全限制。

## 5. 验收步骤

使用当前受限样本模式，至少完成：

1. 地图主页收起状态与样图一致。
2. 底部面板可稳定展开、收起。
3. 网格可连续滚动，缩略图不会错位。
4. 点击单张照片进入图迹内部全屏预览页。
5. 预览页时间、路径、序号及上一张/下一张正确。
6. 预览页双指缩放只作用于系统缩略图；「在原生相册中查看原图」能打开准确照片。
7. 从预览页进入原生相册、返回预览页、再返回地图，状态完整保留。
8. 点击聚合标记能打开统一底部面板，聚合组照片全部可见。
9. 点击右下角按钮后才请求位置权限，成功后显示当前位置蓝点及精度圈并移动地图。
10. 只授予大致位置、拒绝权限、永久拒绝、系统定位关闭和定位失败均有正确处理；照片地图仍可用。
11. 定位为单次操作，完成后停止；无后台定位、无位置历史。
12. 地图快速移动时不会出现大量过期图片请求。
13. 空状态、加载状态和权限错误状态正确。
14. Debug 诊断入口可用，正式界面不显示诊断按钮。
15. Debug 构建成功，安装到 X300 Pro 实机验证。
