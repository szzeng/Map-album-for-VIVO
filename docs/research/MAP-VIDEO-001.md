# MAP-VIDEO-001 视频数据验证

## 范围与已知契约

Debug 菜单“视频 GPS 验证”读取当前授权的 `external_primary` 最近最多 20 条视频，按拍摄时间和 ID 降序；时间缺失时显示未知。默认只取 `DCIM/Camera/`，可切换至所有目录；两种范围各最多 20 条。仅以这些视频 ID 查询 vivo `mediaextra` 的 `_id`、`latitude`、`longitude`。不保存视频、ID、坐标或缩略图，不对视频读取原始内容。复用 `ThumbnailLoader` 的 `loadThumbnail` 和内存缓存。页面离开时取消请求并清理缓存。核对按钮通过系统打开外部视频应用，本应用不内置播放器。

已有研究确认 Provider 存在 `media_type`，但只观察到图片样本为 1，视频取值和类型契约尚未验证；也没有已验证的卷身份契约。因此同 ID 记录一律标为候选，空值、零值、无效值及缺行都不能证明视频本身没有位置。多个同 ID 行标为身份无法确认。坐标范围有效不代表地点正确或坐标基准已知。未发现已验证的 vivo 公开视频缩略图接口，采用 Android 标准接口。

Android 13+ 的视频权限仅在 Debug manifest 声明；Android 14+ 支持所选照片和视频的可见范围。拒绝授权只影响此页面。媒体授权和查询之间仍可能变化；重新进入或刷新页面时重新读取。

## 验证状态

- Debug 与 Release 构建成功；合并 Manifest 中仅 Debug 声明 `READ_MEDIA_VIDEO`。
- 照片数据层、聚合及搜索 JVM 检查通过。Debug 包采用独立包名安装到 V2502A / Android 17，不覆盖正式应用。
- 首次实机列表查询因误用 `date_taken` 字面量失败；改用 Android `DATE_TAKEN` 常量后，用户确认修正版可以使用。用户确认缩略图与视频对应，拒绝视频权限后照片地图正常。
- 最初全部目录列表主要显示微信保存的视频；改为可选相机目录后，用户确认相机视频对上，判断有位置视频的候选坐标应该与实际地点一致；并确认核对过一段相册详情无位置的视频，验证页未显示坐标。这是少量样本的初步人工判断，不构成 Provider 类型或卷身份契约。部分授权及其他来源视频的位置仍待验证。真实坐标、媒体 ID、URI 不记录于本报告或日志。
- 后续用户表示已经核对、没有问题；未提供部分授权或其他来源视频的逐项结果，因此这些具体覆盖范围仍未单独确认。
