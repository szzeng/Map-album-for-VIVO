# MAP-002 V3.1 · 只读架构草案（未通过验收）

候选数据流：用户授权的 MediaStore 图片 ID 和 URI → vivo Provider 的 ID 受限只读查询 → 临时内存结果 → 地图层。不得读取照片 EXIF 提取 GPS，不使用 SQLite / Room 或持久化文件保存 GPS 及关联。所有坐标和关联仅在受控查询期间保存在容量上限 20,000 的临时映射；本次试验的映射在查询结束后释放，尚不构成可复用的地图缓存。

探针在后台单 worker 执行，使用 SelectionArgs 和 Cursor 自动关闭，10 秒发出 CancellationSignal，失败不重试；查询结束或 Activity 销毁时释放映射和任务。只请求当前可见主卷的 ID；检测到多个外部卷时停止。范围过滤、排序、MIME、缩略图和完全撤销权限仅按实测范围成立。

当前代码是验证探针，不是可供 MAP-003 使用的数据 API。正式设计仍需要：可验证的卷与媒体身份、部分选择变化及异步权限撤销处理、容量受限可清空的内存缓存、请求合并和取消、Provider 无响应时的隔离、足够低负载的视口与全库策略，以及不暴露任何不可见媒体的规则。没有这些证据前不得直接展示结果；接口异常时应停止使用，不得自动回退到 EXIF 全库扫描。

V3.1 同时要求验证新增、编辑和删除，又禁止新增、修改或删除任何照片；本次执行以严格只读为准，不人为制造这些变化。只有通过已自然发生的变化或用户另行明确调整任务边界，才能覆盖对应场景。

部分照片授权的实机验证表明：权限标志、用户选择和 MediaStore 实际可见集合必须分开处理。每次用户返回应用或变更授权时应停止显示缓存并重新验证可见集合；缓存本身的清空、重选移除和查询过程中的竞态尚未实现或完成验证。正式授权重选应由用户主动操作触发，参见 [Android 部分照片访问](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。

## 有界内存缓存原型

`EphemeralGeoCache` 使用固定容量 LRU，只保存在进程内；逐项取值必须调用由使用方提供的“当前有权限且身份已验证”检查，检查拒绝或异常时删除并不返回；提供整体清空方法。合成单元测试覆盖容量淘汰、不同卷相同 ID、权限/身份检查拒绝和异常、清空及无效坐标。测试只验证缓存类，不证明当前 MediaStore 与 vivo 的照片身份关联，也不证明真实权限变更时调用方能及时调用清空。该类尚未接入地图，也没有可被视为正式安全接口的验证器。

测试工程的 `ProbeReceiver` 仅用于 ADB 一次性诊断，并以系统 `DUMP` 权限限制发送方；它不是产品后台服务。系统曾延迟冻结后台应用中的任务，不能把广播发送成功视为查询已执行，需以结果日志为准。实时地图实现不能依靠持续广播或后台轮询。


## 授权失效实验原型（2026-11-24）

`GuardedGeoStore` 是独立的实验性内存原型，不与真实 GPS 加载器或地图连接。它使用有上限的基础类型数组与代次标记；显式失效时清空持有的数组引用、使旧代次失效并发送取消信号。新结果须使用当前任务令牌且标记已完成范围检查；读取时由调用者提供可见性与身份检查，返回拒绝或抛出异常会清空缓存并取消当前令牌。这里的范围检查标志和验证器本身不等同于 Android 实际授权验证，也不能解决两个 Provider 之间的原子性问题。不能将此类作为正式数据接口。

在 X300 Pro 上运行了合成数据的同进程检查：失效清空、拒绝旧令牌、检查拒绝/异常、错误顺序、以及后台线程被延迟后在失效完成时提交旧结果，均符合原型预期。另以真实 Activity 生命周期测试：放入一个合成点后切换到桌面，同一进程的 `onPause` 记录取消和清空；返回时记录旧数据不可用，并通过 MediaStore 读取实际可见图片总数 79,147。记录见 `evidence/MAP-002-v31-guard-lifecycle.txt`。

这并非真实权限变化的同进程测试：上次重新选择照片导致进程退出，此次测试没有更改系统授权。生命周期试验只验证 `guard_lifecycle_test` 诊断分支，没有把 guard 接入完整加载器、真实身份验证器、地图显示或前台恢复后的自动重建。仍需在真实授权变化及查询竞态下验证可见集合、请求取消、结果发布、异常与非合作 Provider 行为；不能把仅以权限标志或可见总数作为校验。

进一步尝试对探针单独执行 `READ_MEDIA_IMAGES` AppOp 的 ignore，再切后台并返回；探针进程 PID 不变，合成缓存被失效，但重新读取的 MediaStore 可见数量仍为 79,147。试验期间没有独立读取 ignore 状态，且实际可见范围没有收缩，因此既不能认定权限被有效撤销，也不能将其作为真实授权变化验证。随后执行 AppOp allow，并通过新的探针查询确认完整授权下仍实际可见 79,147。记录见 `evidence/MAP-002-v31-guard-appop-attempt.txt`。


## 真实小样本与生命周期组合试验

实验性 `guard_live_test` 将 guard 和真实只读查询连接，但不向界面或其他组件输出坐标。每次进入前台先清空旧缓存，在单个后台线程从 MediaStore 读取最多 500 个可见主卷图片 ID，向 vivo Provider 查询对应坐标，再使用 MediaStore 的 ID 受限查询复核全部所选 ID；复核不完整、查询失败或请求代次失效时不发布。仅在进程内保存有界数组；进入后台时清空 guard 的引用并发送取消信号。guard 的范围校验标志由这个测试调用路径设置，不构成跨 Provider 的原子授权保证或照片身份验证。

完整授权下的一次实机试验中，MediaStore 可见 79,147 张，500 个样本 ID 均在复核中仍可见，Provider 返回 500 行，461 个非零且数值有效的坐标进入临时缓存；同一进程切后台记录缓存清空，返回时重新查询、复核并重建了 461 个点。另一次在 Provider 查询返回之后、复核之前人为等待最多 5 秒；切后台后 guard 清空并取消旧令牌，返回后旧任务报告取消，新任务重新读取和复核 500 个 ID，重新载入 461 点。这验证的是查询返回后、发布前的生命周期竞态，不证明远程 SQL 执行中可中断。结果日志：`evidence/MAP-002-v31-live-guard.txt`。

两次试验期间系统真实授权范围未变化；部分授权被重新选择、被移除或查询中收缩的同进程行为仍未验证。复核结束与结果被使用之间仍存在非原子窗口，同 ID 并不保证厂商关联或卷身份可靠。临时数组在工作线程处理期间仍由线程局部变量持有，取消和退出方法后才不再有意持有；并无立即垃圾回收或内存清零保证。该试验不是生产 API，不应对地图暴露这些坐标。

并发边界补充：guard 的调用者验证器可能阻塞，因此实验代码先读取代次和点，再在锁外运行验证器，最后重新检查代次；失效或刷新期间不返回旧点。同一加载令牌只允许成功发布一次。X300 Pro 上使用合成坐标让验证器在另一线程等待，同时执行失效；等待结束后读取返回空，迟到发布同样被拒绝。修正后再次以真实 500 ID 验证加载、后台清理及返回重载，结果仍为 461 点。日志 `evidence/MAP-002-v31-guard-race.txt`。这不能消除返回数据后、界面使用前系统授权变化的窗口，仍不是生产安全接口。

诊断并发保护补充：真实小样本加载与原有一次性探针共用进程内查询门闩。在 X300 Pro 的受控试验中，前者等待复核期间发送一次另一探针请求，后者记录 `already_running` 并停止；前者随后正常完成。见 `evidence/MAP-002-v31-guard-single-worker.txt`。该门闩只覆盖本探针进程，不是跨进程、系统或正式应用的负载保证。


## 实际部分授权的加载与重新选择

2026-11-24 用户将探针设为部分照片授权。Android 报告完整图片权限未授予、所选图片权限已授予；MediaStore 实际可见 5 项，真实加载器只请求和复核这 5 个 ID，其中 5 个有效坐标进入临时缓存。用户进入系统权限设置时旧 Activity 的 `onPause` 记录缓存清空。用户重新选择照片后，旧探针进程已结束；新进程从空缓存重新查询，实际可见 5 项，5 项复核，4 个有效坐标进入临时缓存。用户说取消了部分原选择并增加了其他照片，但两次未保存或跨进程比较 ID，不能根据数量或用户操作推断具体集合差异。

用户随后恢复全部照片授权，重新查询确认 MediaStore 可见 79,147 张，与测试前一致。记录见 `evidence/MAP-002-v31-live-partial-reselection.txt`。此次验证覆盖真实部分授权、进入权限设置时旧缓存失效、进程被结束后的重新加载；不能证明系统保留同一进程时的真实授权变化处理，也不证明 Provider GPS 与照片的身份契约。输出只记录聚合数字，不保存照片 ID 或坐标。


## 内存视口过滤原型

`ViewportFilter` 是纯内存工具，扫描基础类型坐标数组并向调用方提供的缓冲区写入匹配的数组下标；返回完整命中数，缓冲区不够时可由调用者识别截断。纬度、经度边界包含端点；跨日期变更线使用西经界大于东经界的形式，+180° 和 -180° 按同一条经线处理。它不查询 Provider，不执行授权或媒体身份验证，也不构成地图数据接口。

在 X300 Pro 上，以合成坐标测试普通范围、跨线两侧、±180° 端点、非法范围与不足容量；又以真实图库 20,000 个可见 ID 对应的 17,662 个有效数值坐标进行一次筛选。78 个普通视口结果的数组下标与另一段线性参考筛选逐项一致，重复查询逐项一致；扩大视口包含全部原视口下标；跨线和世界范围与参考一致。所选真实窄跨线视口有 0 条，故其端点和两侧仍只有合成证据。单次原型筛选约 816 微秒，供参考，不是交互延迟分布。

同一批授权 ID 下，Provider 范围查询返回的 78 个 ID 与内存结果一致，单次 Provider 查询及遍历 222 ms；这不代表全图库范围查询开销，也不能直接用来预测不同设备或视口的平均耗时。测试只记录统计值，过滤结果不出进程，详见 `evidence/MAP-002-v31-viewport-array.txt`。

聚合输入补充：在 X300 Pro 的 2,000 ID 样本（1,864 个坐标）上，将普通视口筛选出的 234 个数组下标送入一次临时四区计数；计数之和与筛选数相同，并与参考筛选出的输入逐区数量一致。其余坐标未进入这次计数；没有生成正式聚合算法或保存结果。日志见 `evidence/MAP-002-v31-viewport-aggregation-input.txt`。
