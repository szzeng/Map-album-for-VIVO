# MAP-002 V3.1 · Provider 负载验证（进行中）

X300 Pro / Android 17，普通应用、主卷用户授权图片；应用只读，无后台轮询、无并发压力测试。最近 500 个 ID 的一次 Provider 查询及遍历耗时 10 ms；包括目录计数、两个 Provider 查询、缩略图读取的整个任务耗时 74 ms。100 张的整次任务 102 ms。各仅一次实测，不能比较为规模趋势，也不是 P50/P95 或峰值。

500 条查询后，测试应用 `dumpsys meminfo` 报告总 PSS 约 30,505 KiB；这是事后快照，不是峰值，不可归因于某次查询。观察到的 vivo 相册进程在查询前后仍存在；这不能证明无卡顿、锁等待、ANR 或服务负载。

仍缺：原生相册空闲和用户浏览时的成对基线、相册处理新照片期间的对照、长短视口查询的独立耗时和返回规模、取消是否被 Provider 真正响应、退出清理、CPU 峰值与内存峰值、锁等待和 ANR、全库访问策略。应用发出 10 秒取消请求，但系统 Provider 如果不响应不能保证硬超时。已有目录约 7.9 万张；不要通过高频小批量查询来推测或替代全库安全验证。当前证据不足以认定负载满足正式应用要求。

## 原生相册前台浏览时的单次试验

用户让 vivo 相册保持前台并正常浏览时，以一次性后台广播启动单 worker 查询；系统前台 Activity 确认为 vivo 相册。最近 2,000 张授权图片 ID 中，Provider 返回 1,998 个唯一同 ID 项、2 个未匹配；返回项 MIME 1,998 个相同，GPS 非零且在数值范围 1,864、空值 134。Provider 一次查询与遍历 17 ms；包含目录计数、Provider 范围复查和缩略图的任务 121 ms，应用 worker 线程 CPU 18 ms；不含 Provider 进程 CPU。用户随后表示查询期间没有察觉明显异常。完整脱敏日志：`evidence/MAP-002-v31-readonly-2000-gallery.txt`。

这是一次短查询和一次主观观察，不证明不存在锁等待、ANR、峰值或原生相册后台处理期间的影响，也不证明全库访问可接受。未匹配两条可能尚未建立扩展记录、失效或存在其他原因，尚未复核，不得直接解释为无 GPS。

20,000 项一次有界 ID 查询及遍历单次 98 ms；之后三批分别 102、103、87 ms，目录计数与各批总工作耗时约 184、235、240、228 ms。每批间隔约 5 秒，为一次性覆盖统计；不是地图操作时持续查询的推荐策略。未同时采集 Provider 独立 CPU、锁等待或内存峰值，因而不能据此认定全量访问对相册无影响。

补测中预先取消查询返回 `OperationCanceledException`，不代表运行中的 Provider 查询响应取消；无效投影触发异常后，同一进程一次正常样本查询成功。尚未测量真实超时、运行中取消、Cursor 服务端释放或负载峰值。参见 `evidence/MAP-002-v31-wrap-cancel-error.txt`。

## 遍历取消与退出合并试验

2,000 ID 的只读查询返回 Cursor 后，在第一行遍历时主动取消；客户端检测到取消，Cursor `isClosed()` 为 true。同一进程随后以 500 ID 运行正常查询、普通视口和跨日期变更线范围比对，并成功读取一张缩略图。另一次测试人为在首行暂停最多 3 秒，在 Cursor 打开时通过返回键退出探针 Activity；约 1 秒后记录取消异常及客户端 Cursor 已关闭。日志仅含聚合结果：`evidence/MAP-002-v31-cursor-exit.txt`。

该测试覆盖的是查询已返回后的客户端遍历和 Activity 正常销毁；不能证明 Provider 远端 SQL 执行期间可中断、远端游标或锁何时释放，也不覆盖强制终止、ANR 和无响应 Provider。等待仅作为单次受控诊断，不用于正式查询策略。
