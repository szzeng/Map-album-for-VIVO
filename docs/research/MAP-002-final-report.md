# MAP-002 V3.1 · 技术决策（阶段性，尚未完成验收）

日期 2026-11-24。结论：**暂不进入 MAP-003，亦不将 vivo Provider 作为已验收的正式依赖。** 原因是照片与卷身份、部分授权移除、查询取消和原生相册负载仍缺必要证据；不是已经证明 Provider 不可用。继续遵守只读和不建第二套 GPS 数据库的原则，不自动切换 EXIF 方案。

## 已有实测

普通应用已取得 vivo normal 权限并可只读查询。MediaStore 授权主卷当前有 79,147 张图片；分四批查询，79,144 个 ID 和 MIME 与 Provider 返回匹配，3 个缺项；69,637 个坐标非零且数值范围有效，约占 87.98%，其余为空、零坐标或缺项。四批的总数一致但不是同一事务快照。每批约 2 万 ID 的 Provider 查询及遍历分别为 98、102、103、87 ms；一个样本视口的结果和排序与内存计算一致，一张授权图片的缩略图读取成功。完全撤销照片权限时探针停止查询；部分选择和重新选择时 MediaStore 可见数量分别为 8 和 17，系统设置恢复全量授权后可见数量回到 79,147。

分批统计不是同一事务快照，亦不证明照片位置逐一正确；结果不能外推到视频或其他卷。坐标没有被写入报告或日志。原有合成 JPEG 结果作为历史测试保留，V3.1 真实图库试验没有创建、修改或删除照片，也没有读取原图 EXIF、创建 GPS 数据库。

## 待完成与不能推断的事项

- 主卷授权图片已有分批覆盖统计，但非事务快照；视频、其他卷、Provider 全部记录和不可关联的真实原因未知。
- ID、MIME 同值不证明坐标对应真实照片，也不证明 Provider ID 与不同存储卷绑定关系；外置卷、历史残留、跨卷冲突和真实坐标基准仍未知。
- 部分照片授权和重新选择已观察到可见数量变化，但未比较重选前后具体 ID 集合；查询中撤销、删除和 URI 失效尚未验证。
- 仅验证了样本 ID 条件下的视口查询，无法推断不带 ID 条件的全库视口查询是否高效或不会暴露未授权记录。四批单次耗时已测，原生相册前台浏览时用户一次未察觉异常；后台处理照片期间的卡顿、锁等待、ANR、CPU 和内存峰值仍未知。
- 不人为制造新增、编辑或删除照片，因为本任务同时明确禁止这些写入；自然变化或用户调整边界后才能验证这些情形。
- 有一个未接入地图的 LRU 内存缓存原型和合成测试，但暂无满足权限、取消、关联和安全门槛的 MAP-003 稳定数据接口；现有工程仅为验证探针。Provider 的取消请求并非硬超时保证。

## 暂停条件与后续路径

2026-11-24 用户明确取消手机重启验证；该项未验证，也不再安排。由于严格只读约束，不能为了测试而新增、编辑或删除照片；相册正在处理新照片、删除后关联和修改后的更新仍未覆盖。Provider 没有已核实的跨卷关联契约，当前单卷设备也不能证明跨卷安全。申请权限状态与 MediaStore 的实际可见集合曾出现不一致，且授权范围可能在两次独立 Provider 查询之间变化；现有探针不保证跨 Provider 原子授权检查。现有证据不足以判断接口稳定性与负载满足正式使用要求，按 V3.1 暂停将其作为生产依赖，也不进入 MAP-003。

可供用户选择的后续路径：

1. 继续维持 V3.1，只使用真实自然发生的数据变化，在有独立外部卷的设备上验证卷身份；向 vivo 询问第三方支持、权限及 ID 契约。其间不对地图层开放未经验证的坐标。
2. 用户若希望尽早评估单主卷效果，可先明确是否接受单卷、覆盖率、无实时更新及未验证厂商接口的限制；这属于调整验收边界，不能把当前证据描述为完整通过，也不能放松隐私和只读要求。需要另行制定具体验证和风险处理后才能实现。

两条路径均不包括自动 EXIF 扫描或持久化 GPS 数据库。本报告记录当前结果，不代表重启（用户已取消）、相册写入并发、跨卷、查询途中权限变化或正式数据接口已验收。

补充：2,000 项样本的跨日期变更线 OR 过滤与内存结果一致；预先取消在客户端返回取消异常，无效投影异常后同进程可再次查询。测试未证明跨线两侧边界、运行中取消及服务端资源释放，上述暂停条件仍然成立。详细范围及脱敏证据见只读测试报告。

补充合并验证：Cursor 返回后取消遍历，以及 Cursor 打开时正常退出 Activity，两次客户端 Cursor 均记录已关闭；前者随后同进程完成范围查询与缩略图读取。远端执行中取消和服务端资源释放仍未知，不能据此通过资源和负载验收。详见负载验证报告。

授权补充：用户重新选择部分照片时，本次系统结束了原探针进程，新进程只请求了当前可见的 6 个图片 ID；原进程内存缓存随进程结束而丢弃，但无法比较前后照片集合，也不能推广到所有授权变化。随后已实测恢复完整可见范围 79,147 张。详情见媒体关联报告。

进程内数组加载补充：79,147 个主卷可见 ID 一次受控分四批加载，69,637 个非零且数值范围有效的坐标进入有界数组；总计 15,482 ms 包含 15 秒主动批间间隔，Provider 查询遍历合计 271 ms。20,000 ID 样本的内存范围与受限 Provider 视口结果一致，另有合成跨线边界检查；数据身份、授权竞态、资源峰值和后台全程负载仍未验收。详情见性能报告。

授权失效补充：在 X300 Pro 上，合成数据原型通过同进程清空、取消及延迟结果拒绝检查；Activity 切后台再返回时旧合成缓存不可用，并重新查询到 MediaStore 可见数量。真实授权变化、实际可见集合比较和加载器接入仍未完成，不能依据该测试认定生产权限安全。详见只读架构草案。

同进程权限模拟补充：对探针执行 AppOp ignore 后实际可见总数没有变化，未能制造有效的真实授权收缩；恢复 allow 后已再次确认 79,147 张可见。该尝试不能作为权限变化通过证据。

真实小样本缓存补充：500 个当前可见 ID 经 Provider 查询及 MediaStore 二次复核后，461 个坐标进入临时数组；同进程后台清空、返回前台重新读取，以及查询返回后发布前取消的测试通过。权限范围并未真实改变，身份契约与非原子竞态仍未解决，不能作为地图接口验收。详见只读架构草案。

真实部分授权组合补充：探针以 5 个实际可见 ID 加载；进入权限设置时旧缓存清空，重新选择后系统结束旧进程，新进程重新查询并仅加载新可见范围。两轮 ID 未跨进程比较，同一进程内真实权限收缩仍未验证。完整授权已恢复并实测可见 79,147 张。详见只读架构草案。

内存范围补充：基础类型数组筛选原型在 X300 Pro 上通过合成 ±180° 边界和真实 17,662 坐标样本的逐项参考、重复及重叠检查；同批受限 Provider 视口结果一致。真实跨线范围没有命中；授权、身份和服务负载尚未通过验收。详见只读架构草案。

按需媒体访问补充：一张当前授权图片可通过构造的 MediaStore URI 获取一致元数据及缩略图；不存在的 ID、预取消和后台切换时的诊断取消已覆盖。仍不能以此证明 vivo GPS 的照片身份、跨 Provider 原子授权或真实失效 URI 处理。详见媒体关联报告。
