# MAP-001 V2 · vivo X300 Pro 足迹地图 GPS 复用调查

**最终结论 D：证据不足。** 已从这台 X300 Pro 的相册 APK 确认足迹地图会使用已有位置数据，也找到了一个声明 `normal` 权限的导出查询入口。实机 ADB shell 在打开时被拒绝。本次未安装普通应用，因此仍缺普通应用合法访问、有效坐标、照片关联和稳定性证据。工程路线建议先采用 **首次按需解析 EXIF + MediaStore 增量同步**。

调查日期 2026-11-24。设备 vivo V2502A，OriginOS 7，Android 17 / API 37，原生相册 11.0.6.8。结论限定该设备、系统构建和 APK 版本。四个分析 APK 的本机与设备 SHA-256 均已核对。

## 核心问题

| 问题 | 答复及证据类型 |
| --- | --- |
| 足迹地图的 GPS 从哪里来？ | **静态证据**。足迹走相册内部聚类及媒体读取器，按分支从媒体查询坐标列取值，或按媒体 ID 批量映射扩展表坐标。相册扩展逻辑会读取图片 EXIF 填充坐标，实机 MediaProvider APK 也有独立 EXIF 扫描与内部入库逻辑。**未知**。当前图库选择的实际分支、有效行覆盖率和照片来源分布。 |
| vivo 有自己的照片位置索引吗？ | **静态证据**。`gallery-mediaextra.db/MediaExtraTable` 保存媒体关联、GPS、时间字段和代次。`geo.db` 支持坐标与地址映射，足迹另有可持久化的聚类缓存。**未知**。当前用户图库里是否已完整建表填充并可重用。 |
| 有标准或 vivo 自定义接口吗？ | **实机**。注册 `media` 和数个相册相关 Provider。**静态证据**。公开 MediaStore 有媒体目录和增量能力，目标 APK 将外部查询的坐标列置空。vivo 有独立 Provider，多个路由是签名特权，还有一个读扩展表的 `normal` 权限入口。查询范围内未找到可引用的 vivo 第三方足迹 API 契约。 |
| 普通应用可以合法读取吗？ | **实机**。`normal` 候选需要其权限，当前 ADB shell 被拒绝。**静态证据**。权限用 `normal` 定义，和特权路由的条件不同。**未知**。厂商支持的三方授权方式、普通签名应用取得授权后能访问的范围及真实返回。 |
| 能获取 URI、经纬度、拍摄时间吗？ | **官方契约**。MediaStore 可为获授权照片提供媒体 URI 和拍摄时间字段，借助用户授予的位置权限和原始文件读取链路可提取照片已有的 GPS。**静态证据**。vivo 扩展表有媒体关联字段、坐标与时间列。**未知**。其普通应用查询能否返回有效坐标、与 MediaStore URI 匹配的媒体 ID，以及可用的拍摄时间。 |
| 如何避免以后再扫描全库？ | 首次按授权建立本地 GPS 索引，保存缺少 GPS 的成功结果。以每卷 version、generation 和变化队列处理新增及修改。对删除、卷变化和权限变化做可见 ID 对账。稳定未变的记录复用本地结果。 |

## 工程决策与成本

建议以 Android 公共接口作为唯一生产依赖。媒体目录和时间来自 MediaStore，坐标来自用户授权后解析的 EXIF，持久队列负责断点续跑，应用私有 SQLite 为地图查询提供位置和空间索引。常规同步按变更数量解析，权限和删除对账只查元数据。当前已确认可用的媒体目录没有提供获验证的 GPS 子集。

Windows 合成数据实测 10,000 张首次约 1.30 秒，解析器读取约 3.91 MB，生成约 144 KiB 的最小 SQLite 表。同代对账约 0.52 秒，原图打开 0 次。100 个修改样本约 0.016 秒。这些是 Windows 热缓存结果。按手机单张假设 2–15 ms，10,000 张首次约 20–150 秒外加目录、事务与任务调度。真实 X300 Pro 冷热缓存、Android 文件打开延迟、图库格式比例、内存和功耗仍待测。 [成本模型和原始基准](fallback-design.md)

兼容性重点是 Android 14+ 部分授权与授权撤销，卷和 MediaStore version 变化导致 ID 映射失效，API 29 及更早缺少 generation，HEIC、RAW 或云端占位文件的访问及格式差异，以及地图坐标体系和时间字段的解释。手机上应用端权限与变化事件需要受控验证。 [Android 能力和兼容性](android-mediastore-analysis.md)

## 是否继续研究 vivo 接口

当前收益最高的补证是厂商确认该导出接口的用途、用户授权边界及支持版本。若存在可依赖的授权契约，可在另一台获准安装验证应用的测试设备上，用已知 GPS 和拍摄时间的少量合成照片覆核媒体关联、授予和撤销、重启及更新后行为。当前证据已定位到实际数据库读取分支，继续扩大 APK 搜索范围对这些问题帮助有限。

下一阶段建议先做索引性能和权限生命周期验证，再接地图视口与照片跳转。测试用例需覆盖首扫暂停恢复、无改动重启、添加、修改、删除、部分选择变化和位置权限撤销。通过条件包括无改动同步不打开原图，以及失去授权的点退出地图查询。
