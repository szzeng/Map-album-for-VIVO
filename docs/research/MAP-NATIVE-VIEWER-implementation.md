# vivo 原生相册接入与实机记录

日期：2026-11-28。设备：X300 Pro / V2502A，Android 17，vivo 相册 11.0.6.8 / 110006008。安装独立调试包 `io.github.szzeng.mapalbum.debug`，未覆盖原有安装。

## 实现

地图单媒体标记和「此处媒体」列表接入 `VivoNativeGalleryLauncher`；列表按现有排序读取完整媒体键，转换为相册私有接口所需的整数 ID 和相同顺序的 MediaStore URI，传入所点位置。仅精确匹配验证过的相册版本才使用私有接口；版本不符、ID 越界、超过上限、Intent 过大或启动异常时完整回退到原有浏览方式。照片、纯视频、混合队列分别采用已验证的入口 MIME 规则。未改写 MediaStore 或 vivo Provider，也未复制媒体。

首版上限设为 128 项，并限制序列化 Intent 大小不超过 64 KiB；后续优化已移除这两项限制，见文末。首版独立探针实机测试了 128 张现有照片的总数、末项和中间位置及相邻切换；并未逐一验证 128 项和各种媒体组合。

## 视频进入时的白色闪屏

实机逐帧检查发现，白色区域出现在 vivo 相册的视频画面内，先于其视频封面加载。现从图迹已加载的缩略图生成有大小限制的临时 JPEG，并通过相册的 `thumbnail_data` 参数传入；视频缩略图尚未加载时会先异步请求。缩略图不写入文件。独立探针及图迹调试包分别测试，修复前同一视频的录屏中出现 3 帧白色画面，修复后的对应测试未观察到白色画面，用户也确认效果改善。

若缩略图获取或压缩失败，仍会不带封面打开原生相册，可能重新出现白色闪屏。该参数同样是相册私有实现，结果限于当前设备和版本。

## 后续优化：大聚合与转场

原来的 128 项及 64 KiB 人为限制已移除。经 X300 Pro 实测，vivo 相册可依靠自身媒体读取权限，用有序 ID 列表和当前 URI 构建队列；因此不再为每一项重复传递 URI 和授权。独立探针以 2000 项照片、16,500 字节 Intent 打开第 1000 项，系统报告约 224 毫秒显示，可前后切换；应用内 189 项混合聚合打开第 1 项，系统报告约 152 毫秒显示，返回后列表保留。25 项混合聚合以第 16 项视频进入，再向前切至照片成功。这些耗时为单次设备记录，不代表所有设备、状态或队列大小的保证，也未逐项检查全部媒体。

启动时加入短渐显动画，并把授权遮罩推迟到图迹停止显示后；返回时仍在显示内容前恢复遮罩和权限核验。照片与视频均尝试传入缩略图。用户反馈大聚合速度已改善、视频不再闪动，但照片显示前仍偶发闪动；一次录屏没有稳定复现，原因和解决方式尚未确认。版本门槛、整数范围检查和启动失败时完整回退保留；没有应用设定的数量上限，但系统事务大小、内存和相册私有实现仍有实际限制。上述精简方式依赖此版本 vivo 相册自身的读取权限，未验证部分媒体授权和权限变化场景，不能推广到其他相册版本。

后续连续录屏在照片进入时捕获到 vivo 页面中的浅色占位。尝试在传入前逐步缩小缩略图并压缩，重新测试同一照片时仍偶发该占位；缩略图缺失不能解释所有闪动。相册代码存在接收缩略图的路径，但何时使用尚未确定，因此照片闪动仍未解决，不应将本次封面调整当作修复结论。

随后用户指出部分照片会先横向显示再转正。所选样本的 MediaStore 方向为 90°；对同一照片录屏发现，直接传系统缩略图时初始画面会横向，先将缩略图逆时针旋转 90° 后，测试中未观察到横向画面。实现现在异步读取照片的 MediaStore 方向，并在传入相册前对缩略图做反向旋转；方向未知时不传照片封面，避免猜测。此对照只覆盖单个 90° 样本，180°、270°、视频及不同媒体来源尚未验证；相册自身浅色占位仍可能出现。

用户反馈方向正常的部分照片仍会闪白。选中的样本 MediaStore 方向为 NULL，先前逻辑因此没有传封面。按需读取单张照片的 EXIF 后传入封面的尝试仍会闪白；独立探针对同一张照片分别传入 JPEG 和 Bitmap，录屏也都出现相册浅色占位，不能据此确认可靠修复。为避免增加无效读取，该 EXIF 尝试未保留。
