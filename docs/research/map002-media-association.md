# MAP-002 V3.1 · 媒体关联（进行中）

普通应用从当前 MediaStore 授权范围的 `external_primary` 中取最近 100 张图片的 ID 和 MIME，使用 ID 参数查询 vivo Provider；100 个 ID 和 MIME 匹配。应用未读取真实坐标到日志、未记录路径，也没有打开原图。另对其中一张可见图片通过 MediaStore URI 成功获取缩略图。

这是同键同类型的关联证据，不是逐张照片地理位置的正确性验证。Provider 返回字段没有已验证的 volume 信息，尚无法排除不同卷、历史残留或同 ID 误关联；测试代码检测到多个外部卷时停止。只有当前 MediaStore 可见的 ID 才会被请求，权限收缩期间的竞态、重新选择、删除、URI 失效和其他卷尚未实测。任何生产接口在这些边界确认之前不应将匹配视为已验证，也不能基于 Provider 自行扩大用户授权范围。

拍摄时间应优先使用 MediaStore DATE_TAKEN 并注明缺失；本次样本中 Provider `origin_date_taken` 均为零，`origin_date_taken_exif` 虽非空，但其语义、单位、时区、有效值和与 MediaStore 的关系未知。文件修改时间不可冒充拍摄时间。

2,000 个授权样本中有 2 个 MediaStore 可见但 Provider 缺行，单项条件复核后仍缺失；因此不应假设 Provider 每张可见照片都有对应记录。仅凭现有证据无法认定这两张照片有无 GPS 或缺行原因。

用户选择部分照片后，仅 8 个 MediaStore ID 可见且被请求；重新选择后可见数量变为 17。两轮未比较 ID 集合，尚不能证明被取消选择照片会从所有缓存中移除。尝试使用 ADB 恢复完整授权时，权限状态显示允许但应用实际仅能看见 1 张；经用户在系统权限设置中选择全部后，才确认实际可见数量恢复。不能把权限标志作为精确可见集，必须以最新 MediaStore 访问结果核对，并清理失效缓存。

主卷约 79,147 个授权图片项的分批统计中，79,144 个存在同 ID Provider 项且 MIME 相同，另有 3 个缺项。四批不是同一快照且未跨批比较 ID；同 ID 同 MIME 仍不证明位置、存储卷或原图内容的语义对应。

拍摄时间补充实测：位置 40,000 起的 2,000 张图片中，MediaStore DATE_TAKEN 均非零；Provider 的两个候选时间字段均为零。因此该样本不支持使用 Provider 时间作为拍摄时间，正式接口应标明 MediaStore 时间来源并处理缺失。
