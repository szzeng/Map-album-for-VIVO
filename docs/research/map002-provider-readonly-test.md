## 现有成果处置

- 已有实机证据：普通应用获得厂商 normal 权限，Provider 导出且可打开；保留原记录，不重新逆向 APK。
- 合成 JPEG 的同 ID、已知 GPS 匹配：仅证明该样本，作为历史结果保留。旧版曾创建并删除测试照片；V3.1 不再执行这条路径。
- 标准 MediaStore、EXIF 与 SQLite 试验：保留历史事实，EXIF 和 SQLite GPS 索引不再作为新方案。
- 本地未提交的 `IndexStore.java` 草稿已放弃；旧探针的 EXIF 及测试照片写入逻辑、SQLite 测试代码已从当前工程移除。
- 尚未验证：真实图库总体覆盖、卷身份、缩略图、视口过滤、负载与权限变化，不能因合成样本成功认定通过。

## 当前小样本

应用只查询当前授权主卷最近 20 个图片 ID，然后以同 ID 条件向 vivo Provider 发起单次只读查询；仅投影 ID、GPS、媒体类型及时间字段。应用不打开照片、不读取 EXIF、不向任何 Provider 写入、不保存 GPS；最多等待 10 秒并关闭 Cursor。只记录聚合统计，不输出照片 ID、坐标或路径。

本次样本 20 个授权图片 ID，对应 Provider 20 条、20 个唯一 ID，重复 0、不在请求 ID 集合内的结果 0。18 条坐标非零且在数值范围内，2 条为空；零坐标及越界坐标均为 0。`origin_date_taken` 非零数为 0，`origin_date_taken_exif` 非空 20，尚未证明后者代表有效拍摄时间。整个任务记录约 75 ms，包含 MediaStore 和 Provider 两次查询、内存处理，不是单次 Provider 查询耗时，也不是冷启动或持续负载结论。

样本只说明最近 20 张的字段数值及 ID 一致，不能推算真实图库 GPS 覆盖率，不能证明 GPS 对应照片或卷身份、坐标语义及时间值准确。`origin_date_taken_exif` 只读取非空状态，未读取 EXIF 照片内容。原始脱敏日志：`evidence/MAP-002-v31-readonly-sample.txt`。

## 扩展样本及范围查询

在同一设备上，按主卷最近 100 个授权图片 ID 查询，返回 100 个唯一同 ID 项，未出现额外 ID 或重复；100 个 MIME 与 MediaStore 一致。GPS 非零且数值在合法范围 84，空值 16，零坐标和越界各 0。拍摄时间 `origin_date_taken` 非零数为 0，`origin_date_taken_exif` 非空 100；不能推断其值的来源、单位或正确性。

在样本 GPS 数据内部选取一个视口，用 Selection、SelectionArgs 和降序排序再查一次；10 个返回 ID 与内存计算预期集合一致、排序正确。一次读取授权样本缩略图成功，耗时 14 ms。包含目录读取、两次 Provider 查询及缩略图的整次任务耗时 102 ms；非独立 Provider 耗时，不代表冷启动、全库或原生相册并发性能。样本不是随机抽样，不可推断全库覆盖率。ID 和 MIME 一致不足以证明照片实际对应、坐标正确或存储卷身份。

脱敏日志：`evidence/MAP-002-v31-readonly-100.txt`。

## 500 张样本和完全撤销权限

MediaStore 当前授权主卷共有 79,147 张图片。按 ID 降序选最近 500 张，Provider 返回 500 个唯一同 ID 行，MIME 均相同；461 条坐标非零且数值在合法范围，39 条为空。Provider 这一次查询及 Cursor 遍历共 10 ms；包含目录计数、样本、范围查询与缩略图的整体 74 ms。一个样本视口返回 86 条，集合与内存过滤一致、排序正确；缩略图读取为 6 ms。这是单次结果和近期样本，不是整体覆盖率，也不是负载或响应时间分布。

临时撤销探针自己的 `READ_MEDIA_IMAGES` 和 `READ_MEDIA_VISUAL_USER_SELECTED` 后启动：两项均显示未授予，探针在媒体及 GPS 查询前停止；随后已恢复两项授权。此测试未改变其他应用权限，未覆盖部分选择、重新选择或查询进行中撤销。完整日志：`evidence/MAP-002-v31-readonly-500.txt`；权限撤销结果见 `evidence/MAP-002-v31-permission.txt`。

因为图库远大于单批上限，当前 500 张样本不是全库统计。不得将它的 92.2% 当成全库覆盖率，也不能把 159 次批量请求的负载简单外推为可接受。

## 未匹配记录复核

再次对最近 2,000 个授权 ID 查询：1,998 个 Provider 同 ID，另有 2 个缺失。对这两个缺失 ID 在同一轮只读复查：MediaStore 仍能看到 2 个，Provider 仍未返回对应行，未见超出请求集合的 ID。不能据此判断它们原照片是否有 GPS，也不能确定原因是相册尚未索引、格式差异还是其他问题。日志只保留数量：`evidence/MAP-002-v31-missing-recheck.txt`。

## 部分授权、重新选择与恢复

用户通过系统选择部分照片后，权限状态为全量 false、部分 true；MediaStore 实际可见 8 张，探针仅查询 8 个对应 ID，Provider 返回 8 条。用户重新选择后 MediaStore 可见数量变为 17，探针仅查询其中 17 个 ID，返回 17 条。由于未保留或比较两轮 ID 集合，无法证明原有授权记录被移除，也不能证明所有重新选择语义。

随后尝试用 ADB 恢复测试应用原有全部授权；`checkSelfPermission` 和 app-op 状态显示允许，但两次查询实际仅能看到 1 张。原因未知，不能仅凭权限标志认定可见范围。用户在系统应用权限设置中明确选择允许所有照片后，重新查询实际可见 79,147 张，与测试前一致。该试验只改动测试应用的授权；最终已确认其实际可见范围恢复。详细聚合日志：`evidence/MAP-002-v31-partial-reselection.txt`、`evidence/MAP-002-v31-full-restored.txt`。

## 主卷授权图片分批覆盖统计

在完整照片授权、单一外部卷下，先用 5,000、10,000、20,000 个 ID 逐步扩大单次查询；20,000 项查询及遍历用时 98 ms。随后按 MediaStore `_id DESC` 依次以偏移 0、20,000、40,000、60,000 获取有限批次，每次仅以用户可见 ID 查询 Provider，查询之间间隔约 5 秒；应用单 worker，无并发或持续轮询。四批的目录总数均为 79,147；批次容量分别为 20,000、20,000、20,000、19,147，Provider 查询及遍历分别为 98、102、103、87 ms。

聚合统计：79,147 个图片目录项中，79,144 个找到同 ID 的 Provider 项（MIME 均匹配），3 个未匹配；69,637 个坐标非零且数值在合法范围（按目录项计 87.98%），9,363 个有空坐标，144 个为 (0,0)，坐标越界或非有限数为 0。零坐标另列，不直接判定为错误；有合法数值不证明地理位置真实或关联正确。仅统计用户当前授权的主卷图片，不是视频或其他卷的全覆盖。

四次查询不是统一快照，尽管每次总数相同，期间的增删、重新排序或权限范围变化仍可能导致重复或遗漏；未保存 ID，无法事后验证不同批次集合互不重叠。故统计是本次分批近似结果，而非严格事务性全库快照。Provider 未返回的 3 条不等于照片无 GPS。原始聚合日志：`evidence/MAP-002-v31-coverage.txt`。
