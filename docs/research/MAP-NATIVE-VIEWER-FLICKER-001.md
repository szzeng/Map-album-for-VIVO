# MAP-NATIVE-VIEWER-FLICKER-001：照片首帧调查

日期：2026-11-28。范围为 X300 Pro / V2502A、Android 17、vivo 相册 11.0.6.8（110006008），以及照片显示区域内部的浅色画面。

## 结论与边界

目前没有足够证据确定浅色画面的绘制者、颜色来源或持续时间，也不能确定 180ms 动画是否放大它。相册的照片缩略图路径是异步加载任务中的候选数据，不保证在 Activity 或图片区域的第一帧就显示。历史录屏已经证明传入 JPEG 或 Bitmap 仍可能看到浅色画面，因此不能把传入缩略图作为可靠修复。现有证据不足以断言它是完全不可控制的 vivo 内部限制，也不足以证明关闭动画能修复；暂不修改生产代码。

后续用户实机反馈：在开发者选项打开过渡动画后，闪白问题消失。这说明系统过渡动画设置是重要影响因素；但目前没有记录具体动画倍率、同一批照片重复次数和逐帧录屏，尚不能确定是系统过渡、图迹的 180ms 动画还是两者相互作用，也不能推断动画关闭时相册内部的具体绘制原因。建议使用系统过渡动画作为当前使用条件，保留现有代码。

## 相册代码证据

设备当前 `pm path` 与历史记录相同，`dumpsys package` 显示当前版本 11.0.6.8 / 110006008。分析的本地 APK SHA-256 为 `9205cd41b1f8f85fe2493788f25e145e563d8115d52691de1869da6024bfa175`，与[历史设备及本地 APK 哈希](evidence/B-apk-hashes.txt)一致；本次没有重新计算设备文件哈希。

使用仓库内 `scripts/InspectApk.java` 和 JADX 1.5.7 定向查看该 APK：

1. `com.android.gallery3d.app.Gallery.j4` 将 Intent 的 `thumbnail_data` 字节数组存入 `thumbnailData`，并将 `bitmap` 存入 Bundle，再启动内部 `PhotoPage`。同一方法还将已验证的 ID 队列参数转成内部队列参数。
2. `PhotoPage.onCreate` 初始化视图后调用 `y7` 初始化数据；其分支调用 `w7`，把两个候选缩略图分别存入 `PhotoDataAdapter`（混淆类 `x3`）。这发生在页面数据初始化过程中，不能等同于已绘制首帧。
3. `x3` 的 `ScreenNailJob.run` 先尝试 `D1(offset)`：只有 offset 为 0 才尝试消费候选；优先使用保存的编辑器 Bitmap，其次传入 Bitmap，最后解码 `thumbnailData`，使用后清空候选。某些已有 screen nail 的条件下任务会提前返回。未取得候选时继续走媒体缩略图等加载路径。这个加载任务与实际屏幕呈现之间的调度和每次首帧的先后顺序仍未通过录屏或追踪确定。
4. `PhotoPage` 存在背景色和内部动画相关代码，`Gallery` 也转发过动画矩形等参数；仅凭这些静态引用不能证明它们对应本问题的浅色区域，更不能证明第三方可用参数能消除闪白。没有发现经过验证、同时保留原生浏览和队列能力的替代首帧入口。反编译存在警告，以上仅限核查到的方法，不能证明不存在其他路径。

## 复用的历史实测

- [接入及实机记录](MAP-NATIVE-VIEWER-implementation.md)：照片区域曾录到浅色占位；同一照片分别传入 JPEG 和 Bitmap 仍出现占位。方向为 90° 的一个样本曾先横向后转正，传入前反向旋转后该样本未再观察到横向画面；其他方向没有充分覆盖。
- 同一记录中，视频封面方案在一次修复前后录屏中由 3 帧白画面变为未观察到白画面；视频播放、混合队列、地图返回和 189 项混合聚合等已有历史验证，详细范围及限制见原记录。这些不是本次回归结果。
- [入口调查](MAP-NATIVE-VIEWER-001.md)记录了原生内部页面不可导出、标准单项 VIEW 和其他入口的实测边界；不推断未经验证的私有参数。

## 未完成的对照与验收

历史记录没有同一批照片、相同条件下 A（相册列表）、B（图迹现有动画）、C（图迹关闭动画）的逐帧对照，不能计算出现率和持续时间。本次遵照优先参考历史调查的要求没有重复缩略图、EXIF 或队列实验，也没有进行新的 A/B/C 录屏或至少 10 次进入测试。照片方向、视频、混合队列、返回地图、大队列及回退均未重新实机回归；历史结果不能代替本次验收。建议后续只补缺失的 A/B/C 对照，固定照片与系统设置、记录每次条件和逐帧时间；在明确结果前不要改动画或图片编码。
