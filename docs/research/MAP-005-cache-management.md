# MAP-005 地图缓存管理：取消记录

状态：2026-11-27 用户决定取消整个功能，已撤回本任务的应用代码和测试；保留本研究记录。首页不增加“存储与缓存”，不提供缓存统计、300 MiB 提醒或手动清理。地图继续沿用原有 SDK 默认初始化和隐私同意流程。代码基线为 `8ce7ddb`（任务所列 `57b333e` 的后继），未回退其后续照片浏览功能。

## 取消原因

百度地图 SDK 9.0.0 的缓存实际范围尚不能可靠划定，无法准确统计地图缓存。实测指定应用专属外部缓存目录后，地图浏览产生的数据仍出现在应用内部缓存；若只统计指定目录，会错误地显示占用很小或为零。SDK 的普通地图清理接口没有完成回调，不能确认清理完成。基于这些限制，用户决定取消整个功能。

## 验证记录

- 从项目实际 SDK 依赖确认存在 `initialize(String, Context)`、`isInitialized()` 和返回 `void` 的 `cleanCache(int)`。任务提供的 9.0.0 在线文档当时无法访问；百度 [7.6.5 接口文档](https://mapopen-pub-androidsdk.cdn.bcebos.com/map/7_6_5/doc/com/baidu/mapapi/map/BaiduMap.html) 描述可按普通地图或卫星地图清理。
- 在 X300 Pro（V2502A / PD2502）独立 Debug 包中，默认初始化时，浏览后内部 `cache/tmp` 的 `du` 占用约 2.5 MiB，触发普通地图清理后约 0.7 MiB，再次浏览后约 1.4 MiB；用户确认清理后地图可加载、应用重启后正常。不能据此推断完整清理范围或所有设备行为。
- 临时实验在首次初始化前传入 `getExternalCacheDir()/baidu-map-sdk`；用户确认浏览正常，自定义目录仍为空，内部 `cache/tmp` 浏览后约 2.9 MiB，清理后约 0.8 MiB。该实验不能证明 SDK 在其他场景不会写入自定义目录。实验实现没有保留在代码中。
- 对本地 SDK 字节码的检查显示，Android 29 及以上默认使用应用外部 files 目录（不可用时回退内部 files），缓存基路径为应用内部 cache 目录。独立 Debug 包的内部 `cache/tmp` 存在地图相关文件，外部 files 下有 `BaiduMapSDKNew`；正式包外部 files 下也有该目录。正式包不可调试，其内部文件、旧版本缓存完整范围以及系统清理外部缓存后的行为未验证。
- 用户对清理后检查回答“一切正常”，但未单独确认照片访问是否启用及各照片功能是否逐项检查；也未做断网缓存复用测试。

实验未覆盖或清理手机正式安装包。手机上曾安装独立测试包 `io.github.szzeng.mapalbum.debug`；其安装与应用代码回滚是两个独立状态。
